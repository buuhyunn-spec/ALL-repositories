SOP #1 Twinhomebuyer AI Readiness Self-study edition

Teaching Google to read your FAQs

128 pages on our site have real questions and answers on them — but Google can only see the words, not the fact that they’re questions and answers. Your job is to add a small, invisible label to each page that spells it out. This guide walks you through it even if you’ve never touched code.

01 — Start here

What you’re actually doing

Nothing on the page changes. You are adding a hidden note for machines that says “this bit is a question, and this bit is its answer.”

Think of a jar of peanut butter. A human can look at it and work out what’s inside. A machine can’t — so we print a nutrition label on the back in a fixed format that every machine understands. Schema markup is that nutrition label, for a web page.

Right now our FAQ pages have no label. Google sees a wall of text and has to guess which line is a question and which paragraph answers it. Usually it doesn’t bother guessing — it just skips the page. Add the label, and the same page becomes eligible to show up as an expandable FAQ in search results, or to be quoted directly by an AI assistant.

👤 What a visitor sees
How fast can you close?

Most cash purchases close in 7 to 14 days.

You do not touch a single word of this. It stays exactly as it is.

</> What the machine reads
{ "@type": "Question", "name": "How fast can you close?", "acceptedAnswer": { "@type": "Answer", "text": "Most cash purchases close in 7 to 14 days." } }

The same words, copied character for character, in a format machines can file.

The question → goes in name The answer → goes in text
Why this job is first in the queue

It’s mechanical, not creative — no new writing, just copying. It’s a quick win at volume — 128 pages, the same fix every time. And it’s a prerequisite — other AI-readiness checks get easier to verify once the Q&A structure is spelled out.

The one rule that outranks all the others

The label must describe what’s really on the page. Marking up a question that a visitor can’t actually see — or wording it differently from the page — is worse than having no label at all, and can get the page penalised by Google.

02 — Decoder

Words you’ll meet

Every bit of jargon in this document, in one place. Come back here whenever a step uses a word you don’t recognise.

Schema markup / structured data
The hidden label. A block of text in a fixed format that tells machines what the page’s content means, not just what it says.
JSON-LD
The particular format we write that label in — the one with all the curly braces and quotation marks. It’s just a strict way of writing “this label = this value”.
FAQPage
The specific type of label used for a page of questions and answers. Other types exist (Recipe, Product, Event) — we only use this one.
Rich result
A search listing with extra bits attached — here, the expandable questions that appear under a link on Google. That’s the payoff for doing this.
@id
A unique name tag for this page’s label, so machines don’t mix it up with another page’s. We build it from the page’s own web address plus #faq.
mainEntity
The list that holds all the questions. Everything between its square brackets is “the questions on this page.”
Elementor
The drag-and-drop page builder we edit WordPress pages with. You’ll open a page in it, drop in one block, and save.
Container & widget
A container is an empty box you drop things into. A widget is the thing you drop in. You need the HTML widget specifically.
Cache
A saved snapshot of the page that the server hands out to be fast. Until it’s cleared, visitors (and you) keep seeing the old version of the page.
Purge the cache
Throwing that snapshot away so the server rebuilds the page fresh. On WP Engine this hits all ~800 pages at once, which is why only the Lead does it.
Incognito window
A private browser window that ignores your saved logins and your own cached copies. It shows you the page the way a stranger sees it.
View source
Right-click a page → “View page source”. Shows the raw code the browser received. Your label lives here, invisible on the page itself.
Validator
A free web tool you paste a URL into. It reads your label and reports mistakes. Two of them are required in Step 9.
Straight vs curly quotes
" is a straight quote and is the only one that works. “ and ” are curly quotes; Google Docs inserts them automatically and they silently break the label.
Escaping a quote
Writing \" instead of " when a quotation mark appears inside your answer text. The backslash tells the machine “this one is part of the sentence, not the end of it.”
AI Readiness tool
The scanner that produced the 128-page list. It crawls the whole site, so it’s slow — the Lead runs it weekly; you never run it per page.

04 — The work

The eleven steps

Do these in order, one page at a time. Steps 1–10 are yours; step 11 belongs to the Project Lead.

1

Get your assigned URLs

In the sheet

Open the task tab and find your section — rows are grouped by name. Pick the next row with nothing in Progress, and set Progress = ongoing as you start it.

In plain English

This sheet is the ticket system — there is no separate tool. Setting ongoing is how you tell everyone else that row is taken, so two people don’t do the same page twice.

2

Confirm it’s genuinely FAQ content

On the page

Open the page and look for real, visible question-and-answer pairs — an FAQ section, an accordion, a Q&A block.

If the page doesn’t actually have Q&A-formatted content, that’s a false positive from the scanning tool. Leave Progress as it is (do not mark Done), write the reason in the Issue column — e.g. “not real FAQ content” — and tell the Lead.

Don’t force it

Never bend content that isn’t a question and answer into a question and answer. Promotional copy and testimonials are not FAQs.

3

Copy the exact visible text

Notepad / VS Code

Nothing needs rewriting. For every Q&A pair on the page, copy the question (the heading) and the answer text verbatim — same wording, same punctuation.

The question doesn’t have to be phrased as a literal question. A heading like “Why Some Sellers Choose an As-Is Cash Sale” is a perfectly valid FAQ question for schema purposes, as long as the text directly below it answers it.

Never use Google Docs for this

Google Docs silently turns straight quotes (") into curly quotes (“ ”). Curly quotes break the label, and nothing warns you — it just fails validation later with a confusing error. Type into a plain text editor (Notepad, VS Code) instead.

4

Build the JSON-LD

Notepad / VS Code

Start from this template. Then make exactly two kinds of change:

  1. Set @id to the live web address of that exact page, followed by #faq.
  2. Include one Question block per Q&A pair already on the page — add or delete blocks so the count matches the page exactly.
Template — JSON-LD 
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "@id": "https://www.example.com/this-exact-page-url/#faq",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Exact visible question/heading text goes here",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Paste the answer already on the page here. Plain text only - no HTML tags."
      }
    },
    {
      "@type": "Question",
      "name": "Second question/heading on the page",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Paste that answer already on the page here too."
      }
    }
  ]
}
Three things that trip people up

Strip HTML tags out of every text value — no <b>, no <a>, plain words only. Escape internal quotes: a quotation mark inside an answer must be written as \". Never invent a question — you are only wrapping the heading and paragraph that already exist.

If a question has no answer under it

Stop and flag it (see When to stop and ask). Do not write an answer yourself.

5

Insert it in Elementor

In Elementor
  1. Edit the page in Elementor.
  2. Scroll to the bottom of the page and add a new container. Leave it completely unstyled — it’s just a wrapper, nothing visual goes in it.
  3. Drag in the HTML widget. Not Text Editor. Not Shortcode.
  4. Paste your whole block from Step 4 into it, wrapped in script tags:
What goes in the HTML widget
<script type="application/ld+json">
{ ...your JSON here... }
</script>
Why the widget choice matters

The Text Editor widget “escapes” code — it treats your label as words to display rather than instructions, which breaks it. Only the HTML widget passes it through untouched.

6

Update / publish

In Elementor

Save or publish the page in Elementor. Nothing visible should change for a visitor.

7

Ask the Lead to purge cache

Ask the Lead
Do not clear the WP Engine cache yourself

“Clear all caches” is a site-wide action — it affects all ~800 pages, not just yours. Message the Project Lead when your page is published and ask them to purge it, or get their go-ahead before you do it.

Mention it too if the page looks off after saving, so they can also run Elementor → Tools → Regenerate CSS & Data.

Don’t skip this

Skipping the purge is the most common way to “finish” a page and then fail your own checks in Step 9 — you’d still be looking at the cached, pre-fix version of the page.

8

Confirm it actually landed

Check

Open the live page in an incognito window, view source (the real page source, not the Elementor editor), and confirm the <script type="application/ld+json"> block is really there, exactly as you pasted it.

Two different checks, both required

“Is the FAQ visible on the page?” is a content check. “Is the script block in the source?” is a markup check. Both have to be true.

9

Validate

Check

Don’t use the AI Readiness tool for this — it crawls the whole ~800-page site, so it’s far too slow to re-check one page. Per page, do these three:

  1. validator.schema.org — paste in the live page URL (or the JSON-LD directly) and confirm zero errors. This is your fast self-check while you’re still working.
  2. Google Rich Results Test — confirm the page shows as FAQ-eligible. Take a screenshot for your own records; the tracker has no column for it, but keep it in case a page gets questioned later.
  3. Look at the live page with your own eyes. Every question and answer you put in the JSON-LD must genuinely be displayed to a normal visitor — not hidden, not removed, not behind a login.
The third check matters as much as the first two

Schema describing content that isn’t visibly on the page is invalid and can get the page penalised, even if both validators pass.

10

Update the tracker

In the sheet

In the task tab, fill in today’s Date and set Progress = Done — only once every check in Step 9 has actually passed.

What “Done” signals to everyone else

Done is read as “this page is fully verified.” Never use it as a placeholder while something is still pending.

11

The Lead’s weekly re-scan

Project Lead only

The Project Lead re-runs the AI Readiness tool weekly — this full-site crawl is a Lead-only step, never a per-page one — and confirms completed pages have dropped off the “FAQ without schema” report. They also spot-check about 10% of Done rows against validator.schema.org and the live page.

05 — Non-negotiable

Rules you can’t bend

Eight things that are never a judgement call. If a page seems to require breaking one of these, that’s an escalation, not a decision.

  • 01 One FAQPage block per page. Never stack duplicates — two labels on one page conflict with each other.
  • 02 Never copy another page’s @id. Always swap in the live URL of the exact page you’re working on.
  • 03 HTML widget only. Text Editor and Shortcode widgets escape or mangle the <script> tag.
  • 04 Never purge the WP Engine cache yourself. It’s site-wide across ~800 pages — always go through the Project Lead (Step 7).
  • 05 Type JSON in a plain text editor, never Google Docs. Silent curly-quote corruption (Step 3).
  • 06 Strip HTML tags out of every answer, and escape internal quotes as \". Both break the label if left in.
  • 07 Don’t touch the visible FAQ content to make this fix. If the on-page copy changes later, the schema has to be updated to match — mismatched schema and content is worse than no schema at all.
  • 08 If a question has no answer text under it, flag it. Don’t write one yourself.

07 — Escalation

When to stop and ask

Hit any of these five and you stop. Leave Progress as it is, write the reason in the Issue column, and message the Project Lead directly. Don’t guess — a guess here creates work for someone else later.

!

The page isn’t real FAQ content — the scanning tool got it wrong.

!

A question on the page has no answer text underneath it.

!

The page already has a different FAQPage block, or a conflicting one.

!

You’re unsure whether something counts as a “question” — e.g. a single Q&A buried in body text.

!

Elementor won’t let you add a container or HTML widget — locked template, page-builder restriction, or similar.
